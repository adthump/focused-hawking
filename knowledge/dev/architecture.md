# 🏛️ 시스템 아키텍처 결정 기록 (Architecture Decision Records)

이 문서는 우현이 일일 관찰 기록표 시스템의 핵심 설계 결정(ADR)과 그 배경, 제약 사항을 기록한 문서입니다. 유사한 작업이나 기능 확장을 진행할 때 반드시 이 설계 의도를 준수해야 합니다.

---

## 📌 핵심 원칙 치트시트 (Golden Rules)

1. **소아청소년정신과/발달클리닉 정기 진료 상담 최우선 최적화**: 이 시스템의 궁극적 존재 목적은 5~10분의 짧은 전문의 정기 진료 시간 동안 의사가 가장 필요로 하는 5대 핵심 임상 지표(복용 순응도, 오후 4시 피크 집중도, 저녁 리바운드, 점심 식욕 부진, 수면/틱 부작용)를 10초 만에 브리핑하고 처방을 상의하기 위함입니다. 아이의 자존감을 보호하기 위해 UI 및 인쇄물에는 병명/진단명을 직접 표기하지 않습니다.
2. **무설치 단일 파일 SPA 원칙**: 사용자 PC(부모님)에서 복잡한 웹팩/번들러 빌드 과정 없이 `index.html` 더블 클릭 또는 바로가기로 즉시 열려야 합니다.
3. **LocalStorage + Node.js 듀얼 스토어 실시간 동기화**: 서버가 없어도 브라우저 자체에 온전히 저장(오프라인 우선)되며, 서버 구동 시 PC와 스마트폰 간 양방향 REST API 동기화가 동작합니다.
4. **Dev-QA 분리 원칙**: 개발 작업(`woohyun-tracker`)과 품질 검증(`woohyun-qa-guardian`)을 분리하여 자가 편향 없는 객관적 회귀 검증(SWUT 19종 + SWIT 11종)을 통과해야 합니다.
5. **한국어 로케일 및 엑셀 호환성**: 모든 날짜는 `YYYY-MM-DD`, 한글 컬럼명 및 인코딩은 손상되지 않아야 합니다.

## 📝 세부 결정 기록 (ADR)

### ADR-001: 단일 파일 SPA (`index.html`) 구조 채택
- **결정**: HTML, CSS, JavaScript를 외부 번들러 없이 `index.html` 내부에 인라인(또는 CDN) 형태로 구성.
- **배경 및 이유**:
  - 부모님이 사용하는 가정용 환경에서 Node.js 환경 설정이나 빌드 오류 없이 가장 단순하고 안정적으로 실행되어야 함.
  - 외부 CDN(Tailwind CSS, Font Awesome, Chart.js, SheetJS)을 로드하되, 오프라인 시에도 기본 기능이 유지되도록 설계.
- **영향**: 새 UI나 차트를 추가할 때 별도 컴포넌트 파일 분리 대신 `index.html` 내부의 함수/컨테이너 모듈화 패턴을 따름.

### ADR-002: LocalStorage ↔ Node.js 서버 듀얼 스토어 동기화
- **결정**: 브라우저 `localStorage`를 1차 저장소로 유지하면서, Node.js 경량 서버(`server.js`, 포트 5500)를 구동하여 JSON 파일(`data/records.json`)과 실시간 양방향 동기화.
- **배경 및 이유**:
  - 클라우드 서버(AWS 등)나 외부 DB 비용/보안 위험 없이 가정 내 동일 Wi-Fi(192.168.x.x) 환경에서 스마트폰으로 편리하게 작성하고 PC 화면에 즉시 동기화.
  - PC가 꺼져 있거나 서버가 꺼져 있어도 스마트폰/PC 각자의 로컬스토리지에 안전하게 보존.
- **엔드포인트**:
  - `GET /api/records`: 전체 기록 조회
  - `POST /api/records`: 일일 기록 저장/수정
  - `DELETE /api/records/:date`: 특정 날짜 기록 삭제
  - `GET /api/ip`: 서버의 로컬 네트워크 IP 반환 (QR 코드 생성용)

### ADR-003: 0초 원클릭 Windows 바로가기 패키징
- **결정**: Electron 대신 경량 VBScript(`바탕화면에_바로가기_만들기.vbs`) 및 배치 파일(`우현이_관찰기록표_실행.bat`, `모바일_접속_서버_실행.bat`)을 활용하여 브라우저의 App Mode(`--app=...`)로 실행.
- **배경 및 이유**:
  - Electron 패키징은 수백 MB의 용량과 느린 시작 속도를 초래함.
  - Chrome/Edge의 `--app` 모드를 사용하면 터미널 창 없이 0초 만에 네이티브 프로그램처럼 실행 가능.

### ADR-004: Dev-QA 에이전트 스킬 분리
- **결정**: 코드를 작성하는 `woohyun-tracker` 스킬과 동작을 검증하는 `woohyun-qa-guardian` 스킬을 독립적으로 운영.
- **배경 및 이유**:
  - 개발 에이전트가 본인이 짠 코드의 버그를 간과하는 문제를 방지.
  - SWUT(단위) 19종 + SWIT(통합) 11종 테스트 스위트를 통해 회귀 결함을 사전에 100% 차단.

### ADR-005: 소아청소년정신과 전문의 진료 브리핑 1장 뷰 & 임상 문진 체계 채택
- **결정**: 웹 애플리케이션 내에 전문의 5분 진료 상담에 최적화된 독립 뷰(`section-briefing`), A4 1장 인쇄 뷰, 모바일 클립보드 텍스트 공유 기능을 통합하고, 일일 기록 폼을 전문 임상 문진 체계로 재정렬.
- **배경 및 이유**:
  - 부모님이 병원에 내원했을 때 의사에게 자녀의 상태를 두서없이 설명하다 핵심(약효 피크, 리바운드, 식욕 저하, 틱)을 놓치는 문제 방지.
  - 10초 만에 전문의가 파악할 수 있는 5대 핵심 임상 지표 카드 및 데이터 기반 자동 질문 추천(`briefingDoctorQuestions`)을 제공.
- **영향**:
  - 상단 메뉴 및 모바일 탭 바에 `[🏥 진료 브리핑]` 전용 경로 제공.
  - `@media print` 스타일을 적용해 데스크탑에서 원클릭으로 A4 1장 인쇄/PDF 저장 지원.
  - 스마트폰 접속 시에는 화면 공간을 확보하기 위해 QR 코드 버튼을 숨기고 4대 핵심 탭(`일일기록, 변화분석, 진료브리핑, 기록목록`) 유지.

### CASE [2026-09-05]: SWVT 시각·반응형 레이아웃 자동 시험 및 5대 섹션 순서 불변 아키텍처 확립
- **내용 및 해결책**: 1) 3대 시험 체계 확립: 기존 로직 단위시험(SWUT 19종), 서버 통합시험(SWIT 11종)에 더해 시각·반응형 레이아웃 자동 시험(SWVT 5종)을 신설하여 총 35종의 다층 무결성 검증 체계 완성.
2) 5대 관찰 블록 순서 불변 원칙: 부모님의 하루 일과 루틴 및 임상 문진 흐름에 따라 1(약물) -> 2(수면/식사) -> 3(오후 4시 수학 집중도) -> 4(저녁 리바운드/감정) -> 5(신체이상/메모) 순서를 불변 규칙으로 확립.
3) 한국어 타이포그래피 표준: word-break: keep-all 스타일을 전역 적용하여 모바일 화면 축소 시 어절 중간 음절 분절(예: '리바운 / 드') 원천 차단.
4) 390px 초소형 뷰포트 안전 표준: 약물 행 2단 flex-wrap, 컴팩트 타임피커(w-8), 100% 균등 분할 세그먼트 버튼 및 Node 26 WebSocket 기반 Chrome CDP 자동 캡처(capture_ui.js) 구축.
