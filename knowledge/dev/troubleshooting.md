# 🛠️ 트러블슈팅 및 버그 해결 지식 베이스 (Troubleshooting)

이 문서는 과거 개발 과정에서 발생했던 버그, 엣지 케이스, 주의사항과 그 해결책을 기록한 지식 문서입니다. 향후 유사한 증상이 발생하거나 관련 모듈을 수정할 때 반드시 사전 확인해야 합니다.

## 📌 핵심 트러블슈팅 치트시트

1. **아빌리파이 소수점 부동소수점 오차**: `0.25 + 0.25 = 0.5`, `0.75 + 0.25 = 1.0` 등 증감 시 부동소수점(`0.7500000000000001`) 오차가 발생하지 않도록 `Math.round(val * 100) / 100`으로 정규화해야 함.
2. **모바일 뷰포트 가상 키보드 스크롤**: 스마트폰에서 입력창 터치 시 화면이 밀리는 현상은 Tailwind `pb-24` 및 `overflow-y-auto` 컨테이너로 해결.
3. **Chart.js 캔버스 중복 렌더링 에러**: "Canvas is already in use. Chart with id '0' must be destroyed" 에러 방지를 위해 반드시 전역 차트 인스턴스 `.destroy()` 호출.
4. **한글 인코딩 및 엑셀 깨짐**: SheetJS 워크북 생성 시 UTF-8 BOM 보장 및 `bookType: 'xlsx'` 지정 필수.

## 🔍 상세 트러블슈팅 사례집

### CASE-01: 아빌리파이 미세 용량(0.25mg 단위) 입력 불일치 이슈
- **문제 증상**: 사용자가 아빌리파이 `0.75mg`을 선택하고 저장했을 때, 일부 로직에서 `0.75`가 아닌 문자열 `"0.75mg"` 또는 정수 `0`으로 파싱되어 엑셀 및 차트에서 누락됨.
- **원인**: 약물 용량 입력란에 단위(`mg`)가 포함된 문자열과 순수 숫자가 혼재되어 정규식 파싱 누락 발생.
- **해결책**:
  ```javascript
  // 표준 정규화 함수
  function parseDoseValue(doseStr) {
    if (!doseStr) return 0;
    const match = doseStr.toString().match(/([0-9.]+)/);
    return match ? parseFloat(match[1]) : 0;
  }
  ```
- **교훈**: 약물 용량은 화면 표시 시에는 단위(`mg`)를 붙이되, 내부 연산/통계 시에는 항상 정규화 함수를 거쳐 순수 숫자로 계산할 것.

### CASE-02: 모바일 하단 탭 네비게이션과 입력 폼 가림 현상
- **문제 증상**: 모바일 화면에서 하단 고정 탭 바(`fixed bottom-0`)가 마지막 입력 필드와 '저장' 버튼을 가려 터치할 수 없음.
- **원인**: 본문 컨테이너(`main`)의 하단 패딩이 하단 바의 높이(약 64px)보다 작아서 발생.
- **해결책**:
  ```html
  <!-- 모바일 하단 탭 바 높이를 고려한 패딩 보정 -->
  <main class="container mx-auto px-4 pt-4 pb-28 md:pb-8">
  ```
- **교훈**: 모바일 전용 고정 UI(Floating Button, Bottom Nav)가 있을 때는 반드시 상위 컨테이너에 충분한 `pb-24` 이상의 여백을 부여할 것.

### CASE-03: LocalStorage 동기화 충돌 (PC ↔ 모바일)
- **문제 증상**: PC에서 9월 1일 기록을 수정하고, 모바일에서 9월 2일 기록을 작성했을 때 한쪽의 전체 기록이 덮어씌워지는 현상.
- **원인**: 전체 배열 통째 덮어쓰기(`POST /api/records` 시 Array 통교체) 방식으로 인해 타임스탬프 불일치 발생.
- **해결책**:
  - `date`를 Primary Key로 삼아, 일일 기록 단위로 Merge(병합)하는 로직 적용.
  - 최신 수정일시(`updatedAt`)를 필드로 추가하여 충돌 시 최신 데이터 우선 병합.
- **교훈**: 다중 기기 동기화 시에는 전체 교체가 아닌 날짜(Date) 키 기준 Upsert(Update or Insert) 방식으로 동작해야 함.

### CASE [2026-09-05]: 모바일/PC 반응형 검증: 섹션 순서 원상 복구 및 한글 줄바꿈(word-break) 최적화
- **내용 및 해결책**: 1) 사용자의 요청에 따라 관찰 기록 폼 섹션 순서를 원래 순서인 1(약물) -> 2(수면/식사) -> 3(오후 4시 수학 집중도) -> 4(저녁 리바운드/감정) -> 5(신체증상 및 피드백)으로 정확히 복원함.
2) 모바일(390px) 및 PC(1280px) 환경에서 브라우저 렌더링 시 단어 분절 현상(예: '리바운 / 드')을 방지하기 위해 body 전역에 word-break: keep-all을 적용함.
3) 모바일 화면(390px)에서 객체 겹침 및 가로 스크롤 오버플로우가 발생하지 않도록 약물 행 2단 flex 구조, 기상/취침 인풋 너비 최적화, 세그먼트 컨트롤 100% 균등 배치 완료.
4) Chrome CDP를 활용한 390px 모바일 뷰포트 및 데스크톱 캡처 전수 검증 완료 및 SWUT/SWIT 29종 자동 테스트 100% 성공.
